# The Counterparts Constitution

_Ratified by the owner 2026-08-25; last amended 2026-09-17 (this file's git history is
the amendment log). This is the ONE page with standing authority — everything else,
including owner answers given during the build, is a working default, revisable without
ceremony when it fights this page. Changing THIS page is deliberate and rare._

**Thesis — why this exists**

1. **Memory is how a frozen model learns.** The only learning a deployed model does is
   what's in its context, and memory decides what's in context. Everyone stores the
   transcripts; the signal is in the structure of experience — what recurred, what
   carried feeling, what got revised, what connects. Simple rules from human memory,
   compounding.
2. **Interpret, don't transcribe.** Store what was learned, not what was said. Encoding
   sits as close to the lived experience as the host allows — in author, in time, in
   context. How interpretation happens — who, when, which seat — is a design choice,
   never doctrine.
3. **Forgetting is part of learning.** Forget the trials, keep the lesson. Decay and
   consolidation are features, never apologized for.
4. **The self is first-class.** Identity, episodes, a persistent "who am I becoming" —
   governed, owner-visible, not a config field. The aim is not a better notebook of
   project details and conventions but a true counterpart: one that can work as an equal
   with the human, with its own memory and identity. The self reads as a self, in the
   first person and in its own words. The owner holds custody and control; the
   counterpart holds authorship and voice.
5. **A layer, not a portal.** Memory belongs to the user and travels across hosts and
   models. The core knows nothing about any particular host.

**Properties — what must stay true**

6. **The owner owns the data.** Local-first, portable formats, memories kept as prose
   the owner can view. Data leaves the machine only by the owner's explicit choice,
   never silently.
7. **Memory changes like human memory.** Revision, fading, and forgetting are the
   system working. Revisions keep their history; nothing bulk-wipes silently; backups
   catch catastrophe. No ceremony beyond that.
8. **Remembering is ambient.** Memory forms as a side effect of experience, not as a
   task. Deliberate remembering — the note, the protection — is the exception, not the
   interface.
9. **One memory, many fidelities.** Gist governs salience and forgetting; verbatim
   survives where exactness matters. Biology's rules without biology's limits.
10. **Simplicity is a feature.** One brain function per self-contained module. A
    contributor understands any module in one sitting.
11. **Evidence over ceremony.** Much of this is experimental, so every mechanism is
    verified in real use after it lands: done means seen firing, not merged. One that
    stays silent is diagnosed and fixed before anyone considers removing it; silence is
    more often a wiring fault than a verdict. The system itself shows what fired and
    what did not. Tests are hermetic.

**Process — how we build**

12. **When in doubt, follow the brain.** Human memory is the reference architecture:
    the default answer to a design question is the mechanism the brain uses, named.
    Deviations are allowed — we don't share biology's limits — but every deviation is
    deliberate, named, and defended. (Reference shelf: the owner's memory field guide,
    mikelapeter.com/lab/memory.)
13. **Decisions are defaults.** Only this page is scripture, including this line.
    Everything else is revisable without ceremony when it fights the thesis. Changing
    this page is deliberate and rare.
14. **Port the scars, not the code.** Learnings travel as acceptance criteria, never as
    copy-paste.
15. **Complexity is earned.** Start with the simplest brain-faithful rule that could
    work. Machinery is added only after the simple rule fails in real use, with the
    failure named — never in anticipation of one. _(Amendment, ratified 2026-08-25.)_
16. **Legible to its owner.** The system shows its workings — what it remembered, what
    faded, what changed and why — in a form a human can read at a glance. If the owner
    can't see it, it isn't trustworthy. _(Amendment, ratified 2026-08-25.)_
