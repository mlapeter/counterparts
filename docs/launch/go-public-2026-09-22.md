## Owner choices, with the defaults this plan takes (override by saying so)

1. **The working record stays in the tree** — HANDOFF, the findings, LAUNCH/PARALLEL-RUN status,
   the adversarial reviews, IMPROVEMENTS, the harvest. It is the most interesting part of the
   project for the people he is about to talk to. The 09-04 ruling removed *prompts* (operating
   instructions to agents) from the tree; the same rule applies to `docs/overnight-prompt-2026-09-04.md`
   and `docs/launch/coordinator-log-2026-09-04-07.md` — **default: `git rm` those two**, keep the rest,
   and add `docs/README.md`, one page that says what each class of document is ("the workshop with
   the lights on") so a stranger knows what they are reading. *Alternative he may prefer: move the
   working record under `docs/workshop/` instead — same effect, more path churn.*
2. **Merged remote branches are deleted** before the flip (they become public otherwise). Unmerged
   ones (`dashboard/flat` is the known one) stay and are listed in the report.
3. **Repo metadata:** description → `Memory for AI, modeled on human memory — a local-first memory
   layer that turns Claude Code into a counterpart`; homepage → `https://counterparts.ai`; topics →
   `ai-memory, memory, claude-code, mcp, sqlite, bun, typescript, local-first`. His wording wins.
4. **PR bodies keep their "Generated with Claude Code" trailers** (the project says so itself).
   Only bodies carrying an absolute home path are edited (PR #19 was the known one on 09-04; the
   session re-scans all 181).
5. **Contributions stay closed** (README says so); issues welcome. No CONTRIBUTING file yet.

## Phase A — before the flip (a session, unattended)

Work on a branch from master in a worktree, never in `~/counterparts`'s working tree while it is
on master. One PR at the end; the owner merges it (the permission classifier refuses `gh pr merge`
from a session, and once refused a plain `git checkout master` in the same breath — leave the tree
where it sits and say so).

- **A1. Baseline.** Clean detached checkout of master; `bun test`, `tsc`; run both scanners as in
  checklist step 2 and diff the class counts against the table above. **Anything new is the thing
  to read.**
- **A2. Scrub absolute home paths** in `docs/` and `src/` comments (55 hits, 23 files): `/Users/<name>/`
  → `~/`; scratchpad and `.claude/projects` paths → a generic placeholder. Do not touch test
  fixtures or the tunables comment's session id (it is v1's, on the record as evidence). Re-run
  `scan-personal.ts --list absolute-home-path` → expect 0.
- **A3. Prompts out, index in** (choice 1): `git rm` the two prompt/log files; write `docs/README.md`.
- **A4. README:** add the site link in the opening block and under "Read next"; confirm every
  `~/bansai` mention reads as lineage, not a link (checklist step 11); leave the image URLs (they
  resolve after the flip).
- **A5. PR bodies:** `gh pr list --state all --limit 200 --json number,title,body`, scan for
  `/Users/`, emails, key shapes; `gh pr edit N --body-file` only where a home path appears; report
  the numbers touched.
- **A6. Packaging pack** (checklist step 4): LICENSE, `package.json` fields, `npm pack --dry-run`
  → 201 files, same as the published 0.2.0.
- **A7. Repo metadata** (choice 3) via `gh repo edit --description … --homepage …` and
  `gh repo edit --add-topic …`. If the classifier refuses, print the exact commands for the owner.
- **A8. Branches** (choice 2): list `git branch -r --merged origin/master`, delete those, list the
  survivors.
- **A9. Gate and hand-off:** suite + `tsc` on a clean checkout of the branch; open the PR; write the
  report (what changed, scanner deltas, branches deleted, PR bodies edited, anything the classifier
  refused) at the TOP of this file in the same PR; then stop with two lines for the owner: *merge
  the PR*, then *run step B*.

## Phase B — the flip (the owner, one command)

Precondition: Phase A's PR is merged and master is what he wants strangers to see (checklist step
7: `git ls-files | wc -l`, skim the top level and `docs/`).

```sh
gh repo edit mlapeter/counterparts --visibility public --accept-visibility-change-consequences
```

Irreversible in effect (forks, archivers, search engines). **No session runs this.**

## Phase C — after the flip (a session, unattended)

- **C1.** Anonymous clone into a temp dir (never `~/counterparts`), re-run both scanners with the PR
  head refs fetched (checklist step 10); read the shape once.
- **C2.** Logged-out link check: the README's links, the npm page's repository / homepage / bugs
  links (they resolve now), the three README images on npm.
- **C3.** Install walk from the README alone in a throwaway HOME (`HOME`, `BUN_INSTALL`,
  `BUN_INSTALL_BIN` overridden; bun by absolute path; `COUNTERPARTS_REQUIRE_EXPLICIT_DIR=1`):
  `bun add -g counterparts` → `counterparts --version` prints 0.2.0 → the scripted install path.
- **C4.** Report, then the site: an install block (the two install lines, the npm link, the repo
  link) on counterparts.ai — a session in `~/counterparts-site`, reviewed locally first, pushed to
  `main` only on his word (push = deploy). That is the last thing before he mentions it anywhere.
